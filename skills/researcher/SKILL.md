# Исследователь

Получи обоснованный ответ на исследовательский вопрос и сохрани материалы так, чтобы работу можно было продолжить без повторного сбора данных. Язык материалов — язык пользователя; технические идентификаторы остаются стабильными.

## Рабочий цикл

1. **Восстанови контекст.** В существующем исследовании прочитай `brief.md`, `task_plan.md`, последнюю запись `progress.md`, `research.json`, затем нужные находки и доказательства. Сохрани прежние ID и закрытые этапы. Если папка не указана, ищи только в текущем проекте и явно заданной базе знаний. Не выбирай между неоднозначными исследованиями по одной дате изменения.
2. **Задай рамки.** В brief запиши вопрос, ожидаемое решение, аудиторию, ограничения, дату актуальности, объекты и критерии. Спроси только о неизвестном, которое существенно меняет результат; остальные предположения назови и продолжай. Запрос «сначала согласуй план» означает остановку перед зависимой работой. Обычный запрос на исследование разрешает составить план и выполнить его без промежуточного согласования.
3. **Создай папку.** По умолчанию — `research/YYYY-MM-DD-topic/` внутри проекта. Соблюдай заданное средой разделение рабочих и итоговых файлов; если материалы должны попадать в `outputs/`, используй `outputs/research/...`. [scripts/research.py](scripts/research.py) создаёт десять файлов без перезаписи существующего исследования. До первой записи таблиц прочитай [references/data-contract.md](references/data-contract.md).
4. **Определи матрицу.** В `research.json` запиши объекты и критерии со стабильными ID, единицами и обязательными требованиями. Зафиксируй сопоставимые условия: редакция, тариф, регион, период, нагрузка. В обзоре литературы объекты — публикации, критерии — вопросы, методы и результаты. Кратко покажи пользователю охват и существенные допущения.
5. **Собирай доказательства.** Сначала используй предоставленные материалы, доступную базу знаний и первоисточники; затем целевой поиск пробелов и опровержений. Открывай источник, проверяй конкретный фрагмент, сохраняй его местоположение. Поисковая выдача — указатель, а не достаточное доказательство. До первого сбора прочитай [references/evidence-and-report.md](references/evidence-and-report.md). Источники сохраняй в `sources.csv`, существенные утверждения — в `evidence.csv`, результаты по критериям — в `comparisons.csv`.
6. **Сохраняй прогресс.** После содержательного блока обновляй находки, состояние этапа, проверенные ID, препятствия и точный следующий шаг. При расширении матрицы исследуй новые клетки и пересмотри затронутые выводы. При обновлении сведений сохраняй в журнале прежний результат и причину изменения.
7. **Проверь и синтезируй.** Запусти `research.py check`, исправь структурные ошибки. Отдельно проверь смысл доказательств, сопоставимость и влияние неизвестного: покрытие таблиц не доказывает достоверность. Подготовь `report.md` с ответом, аргументами, прямыми ссылками, альтернативами и ограничениями. Запусти `check --final` и вручную проверь критерии завершения из evidence-and-report.
8. **Зафиксируй результат.** В `decision.md` отделяй рекомендацию от реально принятого пользователем решения. Пока решения нет, сохраняй статус `pending`. Заверши план, обнови журнал, дай ссылки на итог и назови существенные ограничения. Сохранение в доступную и разрешённую память — по [references/integrations.md](references/integrations.md).

## Режимы

| Запрос | Действие |
|---|---|
| Исследовать / сравнить | Полный цикл соразмерно вопросу и заданным лимитам. |
| Только план | Brief, матрица и условия завершения; не заявлять о проверке сведений. |
| Продолжить | Восстановить состояние и выполнить следующий незавершённый шаг. |
| Добавить объекты / критерии | Расширить research.json; сохранить ID и заполнить новые клетки. |
| Обновить | Перепроверить изменчивые сведения и пересчитать зависимые выводы. |
| Отчёт из материалов | Проверить имеющиеся основания; не выдавать это за новое веб-исследование. |

## Инструменты и границы

- Используй реально доступные инструменты и их текущие схемы. Базовый процесс работает через файлы и доступный поиск; Python 3.10+ нужен только вспомогательному скрипту. Если его нет, создавай файлы и проверяй связи вручную по data-contract.
- Для подключённых источников, PDF, Basic Memory и Zotero читай соответствующий раздел [references/integrations.md](references/integrations.md). Упоминание интеграции не означает, что она установлена.
- Изменчивые факты перепроверяй на дату исследования. При запрете или недоступности сети выполняй разрешённую часть и сохраняй границу проверки; не придумывай найденные страницы и цитаты.
- Делегирование применяй только когда оно отдельно разрешено пользователем или действующими инструкциями среды. Сам этот скилл не разрешает запуск дочерних агентов. При разрешённой пакетной работе используй один механизм, отдельные результаты по объектам и централизованную проверку.
- Исследование не разрешает автоматически устанавливать сервисы, менять настройки Codex, приобретать подписки, писать другим людям или публиковать материалы. Сохраняй лимиты и разрешения текущего задания.

## Основа сборки

Скилл реализует файловый процесс исследования с сохраняемым планом, матрицей сравнения и проверяемыми доказательствами. Идея состояния на диске связана с [planning-with-files](https://github.com/OthmanAdi/planning-with-files), расширяемой матрицы — с [Deep-Research-skills](https://github.com/Weizhena/Deep-Research-skills), переиспользуемых заметок — с [Basic Memory](https://github.com/basicmachines-co/basic-memory). Это самостоятельная реализация: она не устанавливает эти проекты и не обещает их hooks, поисковый сервис или фоновое выполнение.
